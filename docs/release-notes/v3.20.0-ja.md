# CC Switch v3.20.0

> 今回は product-upstream `farion1231/cc-switch` の `v3.19.2..v3.20.0` を selective port で Web-first fork へ同期しました。スタンドアロン Web サーバーのデプロイモデル・デュアルランタイム parity・無認証姿勢・無効化されたデスクトップ updater・既存の Web セキュリティ強化はすべて維持します。本リリースでは今サイクルの 3 つの大型新機能——Pi native coding agent・Codex Alpha WebSearch・managed OAuth アカウント選択——も取り込みました。

## ハイライト

### 新機能

- **Pi native coding agent** —— Pi が一等プロバイダーアプリとして fork に加わりました：プロバイダー管理、プリセットとモデルカタログ、テンプレートライブラリ付きのネイティブ `AGENTS.md` prompt ファイル、セッション検出とセッション使用量インポート、アンインストール状態を保持しパスエイリアスを検証する skills 安全パス。新規 9 個の Web コマンドは登録済みかつルート検査済みのため、Pi はブラウザとデスクトップで同一に動作します。セッション使用量インポートには意味的重複排除台帳を追加する `v16 -> v17` schema マイグレーションが付随します。
- **Codex Alpha WebSearch** —— Codex の Alpha Search エンドポイントをローカルプロキシで提供（ローカルエイリアス 4 個）。Claude 側の hosted WebSearch はリクエスト変換・ストリーミング応答ブリッジ・非ストリーミング応答・usage 集計・約 30 個の markdown 引用プリミティブまで一貫して変換します。URL 導出は fail-closed：`/responses` で literal に終わらない不透明な完全 URL は推測せず拒否します。信頼できないテキスト上の引用重複排除は 5 つの二次コスト上限で制限されます（最悪実測 6.7 s -> 116 us）。
- **managed OAuth アカウント選択** —— プロバイダーを「ログイン中のもの」ではなく特定の managed OAuth アカウント（Codex / Copilot / xAI）に束縛できます。永続化されるのはアカウント id のみで、保存時に OAuth secrets は除去され、再認証が必要なアカウントは保存を**拒否**します。managed Codex Official カードでは選択アカウントの bundle を Codex live `auth.json` に書き込み、ネイティブブラウザログインとフィールド形状を一致させます。ローカルルーティング引き継ぎ中、fork が開放するのは **managed** Official カードのみです——未束縛のネイティブログイン Official カードは切替時に拒否されたままです。この fork は束縛アカウントをサーバー側で解決し、クライアントの inbound `Authorization` を転送しないためです。

### 上流同期（バッチ S1–S7）

- **S1 ドキュメント/プリセット/i18n**：対応する全アプリに PPIO・JieKou AI・XycAi の 3 パートナープリセットを登録（ブランドアイコン付き、対応プリセット型ではエンドポイントフォールバックも保持）；RunAPI プリセットを `runapi.host` に移行（`runapi.co` をフォールバック端点として保持）；メインパネルのプロバイダーカードから旧式のパートナー ⭐ バッジを削除（パートナー星はプリセットセレクタのみに表示）；各言語に `xycai` プロモーション文案を追加；バージョンを 3.20.0 に引き上げ。
- **S2 セキュリティ/データ整合性**：env-check preflight ハング修正；Codex ChatGPT ログインを上書きしない（上記 managed OAuth アカウントの前提）；Kimi thinking インジェクション停止；zhipu `CREDIT_LIMIT` クォータ；routing アニメーション有効化；sync/restore 整合性（トランザクション restore、prepare-once INSERT）；backup SQL 忠実度（複数行 `VALUES` バッチ、trigger/index 順序）。fork の canonical-schema allow-list・backup/replace ロック境界・2s JS deadline・16 MiB heap / 256 KiB stack 上限・SQLite authorizer 厳格性はすべて保持。
- **S3 価格/usage**：DeepSeek V4 peak + Gemini 3.7 Flash シード；DeepSeek catalog ミラー抽出；Grok 4.5 cached + Grok 4.6 + DeepSeek alias；複数年トレンド tooltip；DeepSeek cache-hit トークン。FE-preset ↔ Rust-seed 整合性ゲート合格（`cost=$0` なし）。
- **S4 codex/provider**：Goal モード toggle 削除；1M context toggle 復元；IME-safe プロバイダーフィールド（新規共有 `ImeSafeInput` を Hermes/OpenClaw/OpenCode フォームに採用）；古い device login キャンセル；Grok Build Codex コピー；grokbuild フォーム整列；macOS IME 破損修正。`0455a92c` 複数 follow-login と `897ca892` OAuth usage は分割（フロントエンド増分はこちら；Rust managed-codex トランザクションは上記 managed OAuth アカウントと共に配置）。`40cac1a6` per-model reasoning levels は分割（catalog データ層は配置；transform/UI 層は延期）。
- **S5 UI/refactor**：Hermes/OpenCode/OpenClaw フォーム階層整列；checkbox スタイル統一（Radix → ネイティブ `<input>`、`onCheckedChange`/`checked` 契約を保持）；OpenClaw モデルエディタ；model-dropdown 統合；fuzzy model dropdown（fork が未搭載の共有 `ModelDropdown.tsx` を新規作成）；Claude 詳細オプション整列；エディタ空間削減；GrokBuild glass コンテナ；skills `check_updates` が欠落 SSOT ディレクトリを update として報告。
- **S6 Windows**：起動 FOUC を排除（anti-FOUC インラインスクリプト + テーマ化ウィンドウ背景 + CSP SHA-256）；Windows CLI をレジストリ PATH + スタンドアロンインストーラディレクトリから検出（fork の `services/tool_version.rs` に適応）；WiX Handlebars バックスラッシュエスケープ；WSL atomic-replace フォールバック（fork の 2s deadline + heap/stack 上限を保持）。
- **S7 CI**：PR がフロントエンドにもバックエンドにも触れない場合、該当チェックをスキップ（fork の 3-job `frontend`/`backend`/`web-server` 構造に適応、`changes` job を `dorny/paths-filter`（SHA-pinned）で追加）。

## Fork 固有の差異

- `zh-TW` ロケールと `README_DE` は復元しません。これらに触れる上流 hunk は no-op として破棄します。
- `claudeDesktopProviderPresets` の面と README のデスクトップ専用スポンサーバナー表は引き続き除外するため、上流のデスクトッププリセット・README スポンサー hunk は no-op として破棄します。
- Codex Chat ルーティングスタック（`streaming_codex_chat.rs` / `transform_codex_chat.rs` / `codex_chat_common.rs` / `transform_codex_anthropic.rs`）は意図的な carry-forward 延期項目のままです。このスタックのみに触れる上流コミットは proven-inapplicable としてスキップしました：`3f75bbdf`（StepFun effort）、`46f19a15`（DeepSeek cache-hit トークン、transform 層）、`d01eab97`（OpenCode Zen reasoning）、`6a7da87c`（grokbuild input token details）、および `40cac1a6` の transform/UI 層。スタックを復元するには、まず完全な ~5.7k+ LOC 依存ベースを移植する必要があります。
- `36ed280d` i18n labeler glob 修正はスキップしました。fork には `.github/labeler.yml`（設定）も `workflows/labeler.yml`（ワークフロー）もないためです。その意図——`src/i18n/locales/**` を i18n パスとして正しく認識すること——は `c98cc3a9` のインラインパスフィルタ（`src/**` グループ）で等価にカバーされています。
- `7e5007d5` / `619a592c` Claude Desktop フォームコミットは proven-inapplicable としてスキップ（fork には `ClaudeDesktopProviderForm.tsx` がありません）。`390102a2` OpenCode Go DeepSeek contextWindow コミットはスキップ（fork には "OpenCode Go" プリセットがなく、fork の DeepSeek 公式プリセットは既に `contextWindow` を含みます）。

## 3 つの新機能に関する補足

3 つはそれぞれ独立サブタスクとして計画・ゲート・アーカイブを完了しました。fork 固有の裁定は次のとおりです：

- **Pi**（`84e75ad2` + `40d747c0`）—— 純粋な追加プロバイダーとして移植し、非 Pi パスはリファクタしていません。
- **Codex Alpha WebSearch**（`bdeaac75`）—— 延期中の Codex Chat スタックのうち 1 関数のみ真に必要だったため、唯一の消費者内に**プライベート**関数として配置し、必要性は変異検証済みです。スタック本体は引き続き不在です。
- **managed OAuth アカウント**（`a2e22f33` + `0455a92c` の managed-codex トランザクション）—— 上流の `migrate_legacy_codex_official_managed_binding` startup マイグレーションは**意図的に移植しません**：上流が `v3.20.0` より前に削除済みであり、かつユーザーの現行プロバイダーを固定 `codex-official` id から移動させてしまうためです。引き継ぎ carve-out は上流より狭いです（managed カードのみ、上記参照）。そのため `providerCapabilities.ts` / `ProviderCard.tsx` / `useProviderActions.ts` の Official-takeover 述語は上流と意図的に分岐しています。

`zh-TW` ロケールと Claude Desktop プロバイダーフォームは 3 つとも範囲外です。
