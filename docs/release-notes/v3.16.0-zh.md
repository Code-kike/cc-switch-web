## 概览

CC Switch v3.16.0 将上游 `farion1231/cc-switch` v3.16.0 的改动同步进本 Web 优先 fork，延续了细粒度的 `sync:` 提交方法论。本次的核心变化是**用量统计实时刷新**:用量看板现在会在写入新的请求日志(代理日志、Claude / Codex / Gemini 会话同步、启动归档)的瞬间刷新,而不再等待轮询周期。由于本 fork 跑在两套运行时上,该事件通过运行时中立的 `UiEventSink` 抽象路由——桌面端走 Tauri 事件总线,Web 端走 `GET /api/events` 的 SSE 通道——因此浏览器模式下也能实时刷新。

本版本还对共享后端做了硬化:修复了 Codex 会话同步在非 ASCII 模型名(如 `【官】glm-5.1`)上的崩溃,使 60 秒后台同步定时器不再 panic;在代理层规范化 DeepSeek 的 Anthropic 兼容工具思考历史;并让 Claude 供应商的 deeplink 导入保留通过内联 config 载荷传入的自定义环境变量,而不再丢弃它们。

配置侧,模型与定价目录得到刷新(默认 Claude Opus 升级到 4.8,修正胜算云带前缀的模型 ID 与 GPT 5.5,OpenCode Go 预设去掉模型后缀,OMO 推荐模型刷新并改进"填充推荐"反馈),Rust 的 `seed_model_pricing` 种子数据与前端预设保持一致。最后,Codex 路由层被重构为**不再强制改写用户的 `model_provider` 字段**,与上游对齐并保留每个供应商真实的 `model_provider` id;第三方 Codex 供应商新增远端 compaction 开关。

**发布日期**:2026-05-30

**更新规模**:18 个 sync 提交 | 上游 delta `3c3d4174..8f83fa20`(24 commits,合作伙伴/推广预设已排除)

## 重点内容

- **用量实时刷新(双运行时)**:用量看板在新请求日志落库的瞬间 invalidate 查询,而不再等待轮询周期。刷新事件通过运行时中立的 `UiEventSink` 路由——桌面端 Tauri 事件总线、Web 端 `GET /api/events` SSE——两套运行时都生效。emit 做了 200ms 防抖,因此一次写入数千行的 Codex 批量会话导入只触发约两次刷新。
- **Codex 会话同步崩溃修复(非 ASCII 模型)**:修复了非 ASCII 模型名(如 `【官】glm-5.1`)上"在非字符边界切片"导致的 panic,保护本 fork 的 60 秒后台会话同步定时器不再崩溃。
- **代理:DeepSeek / Anthropic 工具思考规范化**:代理现在会规范化 DeepSeek 的 Anthropic 兼容工具思考历史,提升服务端模式下 Claude 兼容 / DeepSeek 路由的正确性。
- **Deeplink:Claude 导入保留自定义环境变量**:通过 deeplink 导入 Claude 供应商时,现在会保留内联 `config=<base64-json>` 载荷中携带的非标准环境变量(如 `ANTHROPIC_CUSTOM_HEADERS`、`API_TIMEOUT_MS`),不再丢弃。
- **模型 / 定价刷新(含 Opus 4.8)**:默认 Claude Opus 升级到 4.8,修正胜算云带前缀的模型 ID 与 GPT 5.5,OpenCode Go 预设去掉模型后缀,OMO 推荐模型刷新。Rust 定价种子与前端预设保持一致。
- **Codex 路由重构 + 远端 compaction 开关**:Codex 实时配置不再强制改写用户的 `model_provider` 字段;自定义路由 key 统一为 `custom`;第三方 Codex 供应商新增远端 compaction 开关。
- **预发布感知的工具版本检测**:关于页面的工具"有可用更新"指示现在使用正确的 semver 比较(`src/lib/version.ts`),领先于 `latest` 的预发布 / next 通道 CLI 版本不再误报"有可用更新"。

## 新功能

### 用量统计实时刷新

每当 `proxy_request_logs` 表写入新行(代理日志、Claude / Codex / Gemini 会话同步、启动归档)时,会 emit 一个新的 `usage-log-recorded` 事件。前端挂在用量看板上的 `useUsageEventBridge` hook 监听该事件并立即 invalidate 整个 usage 查询命名空间,因此数据无需等待 30 秒轮询周期即可更新。

事件通过运行时中立的 `event-adapter` 投递:桌面端走 Tauri 事件总线,Web 端走 `GET /api/events` 的 SSE 通道。emit 在 200ms 窗口内做防抖,且仅在确实插入了新行时触发(`INSERT OR IGNORE` 被跳过时不会产生空刷新),因此一次写入数千行的批量会话导入只触发约两次刷新事件。

### Codex 远端 compaction 开关

第三方 Codex 供应商在供应商编辑器中新增远端 compaction 开关。

## 变更

### Codex 实时配置保留真实的 `model_provider` id

本 fork 此前会把 Codex 实时 `config.toml` 的 `model_provider` 字段强制改写为一个稳定的内部 `ccswitch` 锚点桶,以便在供应商切换时让 Codex 的 resume 历史保持归组。上游 v3.16.0 移除了这种强制改写(并配套了本 fork 暂未携带的一次性 Codex 历史迁移)。本版本**采纳上游行为**:新写入会保留每个供应商真实的 `model_provider` id,自定义路由 key 统一为 `custom`。行为变更细节见升级须知。

### 模型与定价目录刷新

- 默认 Claude Opus 升级到 **4.8**。
- 修正胜算云带前缀的模型 ID;新增 GPT 5.5。
- OpenCode Go 预设重命名,去掉模型后缀。
- OMO 推荐模型刷新,改进"填充推荐"反馈。
- Rust `database/schema.rs::seed_model_pricing` 与前端 `src/config/*Presets` 保持一致;一次幂等的定价修复 pass 会更新仍带旧价格的历史行。

## 修复

### Codex:非 ASCII 模型名导致会话同步崩溃

`normalize_codex_model` 此前会截取模型名最后 11 字节以剥离 ISO 日期后缀,却未检查切片是否落在 UTF-8 字符边界上。非 ASCII 模型名(如 `【官】glm-5.1`)会触发 panic,拖垮本 fork 的 60 秒后台会话同步定时器。现在该切片由 `is_char_boundary` 和对后缀的 ASCII 检查双重保护。

### 代理:DeepSeek / Anthropic 工具思考历史规范化

代理现在会规范化 DeepSeek 的 Anthropic 兼容工具思考历史,提升服务端模式下 Claude 兼容 / DeepSeek 路由的正确性。

### Deeplink:Claude 供应商导入保留自定义环境变量

通过 deeplink 导入 Claude 供应商时,现在会以内联 base64 config 中的完整 `env` 块(若存在)为基础,再叠加标准 URL 参数字段,从而让用户传入的自定义环境变量在导入后得以保留。

### 关于:预发布感知的工具版本比较

工具"有可用更新"检测现在使用轻量 semver 比较(`src/lib/version.ts`),而非字符串 `!==`。本地安装的、领先于已发布 `latest` 的预发布 / next 通道 CLI 版本不再触发永久性的"有可用更新"误报。

## ⚠️ 升级须知

### Codex `model_provider` 锚点已移除

较早的 fork 构建会把 Codex 实时 `config.toml` 的 `model_provider` 改写为稳定的内部 `ccswitch` 桶,以便在 CC Switch 切换供应商时让 Codex 的 resume 历史保持归组。本版本移除该锚点以与上游对齐:新的 Codex 实时写入现在使用每个供应商**真实**的 `model_provider` id。因此,升级后现有 fork 用户的 Codex resume 历史桶 key 可能发生变化(仅桌面端,影响面较窄)。上游的一次性 Codex 历史连续性迁移**推迟**为后续任务;如果连续性对你很重要,请在该迁移落地前先保留相关 Codex 会话。
