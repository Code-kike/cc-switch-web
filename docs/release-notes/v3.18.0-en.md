# CC Switch v3.18.0

> Product-upstream `farion1231/cc-switch` v3.16.5..v3.18.0 (v3.17.0 + v3.18.0, 125 commits) ported into this Web-first fork in seven themed batches, with the standalone Web server deployment model, dual-runtime parity, and the fork's security hardening preserved.

---

## Overview

This release aligns the Web-first fork with product upstream `v3.18.0`. It is not a blind desktop-source merge: every functional upstream commit was ported, adapted, or explicitly excluded per batch (S1–S7), and Web-only runtime files, the unauthenticated-by-design posture, SSRF/redirect guards, log privacy defaults, atomic/managed config writers, and DB-authoritative MCP projection remain authoritative. Every new command surface ships with exact Web API parity (277 commands, 0 missing routes).

**Release date**: 2026-07-31

## Highlights

### Project Profiles (upstream v3.17.0)

- Snapshot-based configuration switching for Claude Code and Codex: a profile captures providers, MCP enablement, Skills enablement, and the active prompt per scope, and applies them as one operation.
- Switching automatically snapshots the profile you are leaving; proxy takeover is disabled before apply, and the proxy stops when the switch leaves no takeover active.
- Profiles are shared project entities with independent per-scope current pointers; a "never captured" scope is left untouched while a "captured empty" scope clears enabled entries.
- The main-page switcher can be toggled off in Settings (`showProfileSwitcher`).
- Fork scope is Claude Code + Codex only; the upstream Claude Desktop scope is excluded (no Claude Desktop surface exists in this fork).

### Grok OAuth + Grok Build (upstream v3.18.0)

- **Grok Build** is a first-class managed application across providers, proxy takeover, failover, MCP, Skills, prompts, sessions, usage, and the Web UI — with its own curated provider preset catalog.
- **xAI OAuth** device-flow login and account management join Copilot and Codex OAuth in the Auth Center; managed xAI providers for Claude Code and Codex inject tokens only for the pinned `https://api.x.ai/v1` origin, and local token failures do not poison provider health or trigger silent failover.
- **Grok Official** represents the Grok CLI's native login: CC Switch never reads, stores, or overwrites the CLI's native credentials, and that provider cannot be proxy-taken-over. Deleting it is respected; explicit import can restore the canonical seed.
- `grok-4.5` pricing seeds and Codex/Claude xAI presets (native Responses) included.

### Codex usage rebuild + schema v16 (upstream v3.18.0)

- Codex session usage import now aligns parent-rollout token prefixes, identifies parents explicitly, and defers ambiguous files without losing its place; proxy usage keys are stable and collision-safe.
- Session sync is serialized under a process-wide guard in both runtimes, with exactly one refresh notification per pass.
- Schema **v16** migration resets only Codex-derived usage detail rows, rollups, and rollout cursors so they re-import correctly; a **`rebuild Codex usage`** maintenance action (Usage dashboard, both runtimes) can re-run the reset on demand. Both paths hard-fail without an automatic database backup.

### Usage & pricing correctness (upstream v3.17/v3.18)

- Cache-write tokens are accounted with upstream's three-bucket model across all transform paths; stored rows carry explicit input-token semantics so fresh-input math stays auditable.
- Saved usage queries reject transient transport failures so the UI keeps the last good value instead of flashing failures; deterministic failures still surface immediately.
- Prompt-cache breakpoint injection hardening, Codex subagent usage attribution, and dashboard refresh-interval persistence.
- Pricing seeds: GPT-5.6 family (Sol/Terra/Luna, 1.25x cache-write), Hunyuan Hy3, Kimi K3 (+ bare `k3` alias), Kimi For Coding 256K context, plus an OpenClaw list-price reprice with guarded `repair_current_model_pricing` entries that update only rows still equal to the old built-in values.

### Logging privacy overhaul + frontend error persistence (upstream v3.18.0)

- Backend logs are secret-redacted at the source: request logs print origin-only targets (or secret-redacted URLs), body logs are metadata-only at every level, response headers are allowlisted, and crash.log is size-bounded. Desktop logs are no longer wiped on startup.
- Frontend errors (global error/unhandledrejection, React error boundary, startup failures) are captured with a two-layer redaction pipeline and persisted to `logs/frontend.log` in **both** runtimes — Web mode writes through `POST /api/system/log_frontend_error` to server-side disk, so a white-screen crash always leaves a trace.

### Codex routing & protocol hardening (upstream v3.17.0)

- Claude subagent model support; fable model env keys stripped from shared common config and mapped as a proper routing tier.
- TOML basic-string escaping for model names/base URLs closes a live `config.toml` line-injection vector from malicious `/models` responses; a staleness guard drops out-of-date `/models` results.
- Single auth placeholder under takeover (AUTH_TOKEN vs API_KEY, never both), Responses semantic-failure detection inside the retry loop (fails over instead of surfacing dead 2xx responses), tool-schema root `type: "object"` injection, and image-capability inference.

### MCP & config-sync hardening (upstream v3.17.0)

- Live imports for OpenCode, OpenClaw, and Hermes update existing providers instead of only inserting new ones; per-app import failures surface an aggregate error while partial successes persist.
- Save-then-sync toasts for universal providers, switch-time Codex common-config re-extraction/backfill, and structured OpenCode model-limit and header editors.

### Connectivity check refactor (upstream v3.17.0)

- Per-provider test-config overrides are removed in favor of the global connectivity-check settings (the fork keeps its global streaming model/prompt configuration, first-run confirmation, and official-OAuth probe skip).

## Web Adaptations

- Every new upstream Tauri command has an exact Web route and adapter entry: profiles (6 routes), xAI OAuth account/model management, `ensure-grokbuild-official-provider`, `rebuild-codex-usage`, and `log_frontend_error`. Route coverage: 277 commands, 0 missing, 0 method mismatches.
- New shared Rust modules are compiled into the standalone Web binary through the example `#[path]` shims; the Web example test suites (`web_api::`, `dual_runtime_parity::`, `web_proxy_lifecycle::`) cover the parity.
- Frontend features use the runtime-neutral adapter and event bridge (Tauri event bus on desktop, SSE in Web mode) — including profile-applied refresh and usage cache updates.
- Desktop-only surfaces (tray submenus, desktop notifications) remain desktop-gated and do not leak into the Web build.

- Sponsor/referral/marketing content, upstream release packaging/CI, Windows console and tray-language desktop fixes, Windows ARM64.
- Claude Desktop scope and `zh-TW` locale (removed earlier in this fork; not resurrected).
- The upstream Codex Chat Completions bridge cluster (`99e11e08`, `a078b4b2`, `51d6c458`, `f15184ed`, plus four dependent v3.18 fixes) remains deferred — the fork never ported the v3.16.5-era bridge modules it builds on; recorded as backlog.
- Upstream `main` commits past `v3.18.0` (tool-result media bridge, Grok Build usage import, Grok subscription quota) are next-sync work.

## Upgrade Notes

- **Database schema goes v13 → v16** in three additive steps: v14 (profiles), v15 (Grok Build + per-app flags), v16 (Codex usage reset for re-import). Existing databases are backed up automatically before migration; if the backup cannot be created, migration does not run. Too-new databases still refuse startup with recovery guidance instead of downgrade writes.
- After v16, Codex usage details re-import from session logs on the next sync pass; historical Codex totals may shift and become more accurate. The `rebuild Codex usage` maintenance action can repeat this on demand (it also creates a backup first).
- Pricing repair entries update a row only when it still equals the old built-in value — user-modified prices are untouched.
- Log behavior change: `cc-switch.log` persists across restarts under size rotation, `crash.log` is bounded, request/response bodies never reach logs, and frontend crashes persist to `logs/frontend.log`.
