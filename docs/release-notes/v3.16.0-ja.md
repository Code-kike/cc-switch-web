## 概要

CC Switch v3.16.0 は、上流 `farion1231/cc-switch` v3.16.0 の変更を本 Web ファーストフォークへ同期したもので、細粒度の `sync:` 方法論を継続しています。目玉は **Usage 統計のリアルタイム更新**です。Usage ダッシュボードは、新しいリクエストログ（プロキシログ、Claude / Codex / Gemini のセッション同期、起動時アーカイブ）が書き込まれた瞬間に更新されるようになり、ポーリング周期を待たなくなりました。本フォークは 2 つのランタイムで動作するため、このイベントはランタイム中立な `UiEventSink` 抽象を経由してルーティングされます — デスクトップでは Tauri イベントバス、Web サーバーモードでは `GET /api/events` の SSE チャネル — その結果、ブラウザでもライブ更新が機能します。

本リリースでは共有バックエンドも堅牢化しました: 非 ASCII モデル名（例: `【官】glm-5.1`）での Codex セッション同期クラッシュを修正し、60 秒のバックグラウンド同期タイマーが panic しないようにしました; プロキシ層で DeepSeek の Anthropic 互換ツール思考履歴を正規化しました; そして Claude プロバイダーの deeplink インポートが、インライン config ペイロードで渡されたカスタム環境変数を破棄せず保持するようにしました。

設定面では、モデルと価格カタログをリフレッシュしました（デフォルト Claude Opus を 4.8 に引き上げ、ShengSuanYun のプレフィックス付きモデル ID と GPT 5.5 を修正、OpenCode Go プリセットのモデルサフィックスを削除、OMO 推奨モデルをリフレッシュし「推奨を入力」フィードバックを改善）。Rust の `seed_model_pricing` シードとフロントエンドのプリセットは一貫性を保っています。最後に、Codex ルーティング層をリファクタリングし、ライブ `config.toml` の **ユーザーの `model_provider` フィールドを強制的に書き換えない**ようにして上流と整合させ、各プロバイダーの実際の `model_provider` id を保持します; サードパーティ Codex プロバイダー向けにリモート compaction トグルを追加しました。

**リリース日**: 2026-05-30

**Stats**: 18 sync commits | 上流 delta `3c3d4174..8f83fa20`（24 commits、パートナー/リファラルプリセットは除外）

## ハイライト

- **Usage リアルタイム更新（デュアルランタイム）**: Usage ダッシュボードは、新しいリクエストログが着地した瞬間にクエリを invalidate し、ポーリング間隔を待ちません。更新イベントはランタイム中立な `UiEventSink` を経由します — デスクトップは Tauri イベントバス、Web サーバーモードは `GET /api/events` SSE — 両ランタイムで機能します。emit は 200ms でデバウンスされるため、数千行を書き込む Codex の一括セッションインポートでも更新は 2 回程度しか発生しません。
- **Codex セッション同期の panic 修正（非 ASCII モデル）**: 非 ASCII モデル名（例: `【官】glm-5.1`）での「非文字境界スライス」による panic を修正し、本フォークの 60 秒バックグラウンドセッション同期タイマーがクラッシュしないようにしました。
- **プロキシ: DeepSeek / Anthropic ツール思考の正規化**: プロキシが DeepSeek の Anthropic 互換ツール思考履歴を正規化するようになり、サーバーモードの Claude 互換 / DeepSeek ルーティングの正確性が向上します。
- **Deeplink: Claude インポート時のカスタム env 保持**: deeplink 経由で Claude プロバイダーをインポートする際、インライン `config=<base64-json>` ペイロードに含まれる非標準の環境変数（例: `ANTHROPIC_CUSTOM_HEADERS`、`API_TIMEOUT_MS`）を破棄せず保持するようになりました。
- **モデル / 価格リフレッシュ（Opus 4.8 含む）**: デフォルト Claude Opus を 4.8 に引き上げ、ShengSuanYun のプレフィックス付きモデル ID と GPT 5.5 を修正、OpenCode Go プリセットのモデルサフィックスを削除、OMO 推奨モデルをリフレッシュ。Rust の価格シードとフロントエンドのプリセットは一貫性を保っています。
- **Codex ルーティングリファクタ + リモート compaction トグル**: Codex ライブ設定はユーザーの `model_provider` フィールドを強制書き換えしなくなりました; カスタムルーティングキーは `custom` に統一; サードパーティ Codex プロバイダーにリモート compaction トグルを追加。
- **プレリリース対応のツールバージョンチェック**: About 画面のツール「更新あり」表示が、正しい semver 比較（`src/lib/version.ts`）を使うようになり、`latest` より先行するプレリリース / next チャネルの CLI バージョンが誤って「更新あり」を表示しなくなりました。

## 追加

### Usage 統計のリアルタイム更新

`proxy_request_logs` テーブルに新しい行が書き込まれるたび（プロキシログ、Claude / Codex / Gemini のセッション同期、起動時アーカイブ）、新しい `usage-log-recorded` イベントが emit されます。Usage ダッシュボードにマウントされたフロントエンドの `useUsageEventBridge` フックがこれをリッスンし、usage クエリ名前空間を即座に invalidate するため、30 秒のポーリング周期を待たずに数値が更新されます。

イベントはランタイム中立な `event-adapter` 経由で配信されます: デスクトップは Tauri イベントバス、Web サーバーモードは `GET /api/events` の SSE チャネル。emit は 200ms ウィンドウでデバウンスされ、実際に行が挿入された場合のみ発火します（`INSERT OR IGNORE` のスキップは空の更新を生みません）。そのため数千行を書き込む一括セッションインポートでも更新イベントは 2 回程度しか発生しません。

### Codex リモート compaction トグル

サードパーティ Codex プロバイダーに、プロバイダーエディタでのリモート compaction トグルが追加されました。

## 変更

### Codex ライブ設定が実際の `model_provider` id を保持

本フォークは以前、CC Switch のプロバイダー切り替えをまたいで Codex の resume 履歴がグループ化され続けるよう、Codex ライブ `config.toml` の `model_provider` フィールドを安定した内部 `ccswitch` アンカーバケットに強制書き換えしていました。上流 v3.16.0 は強制書き換えを削除しました（本フォークがまだ持たない一回限りの Codex 履歴マイグレーションと対で）。本リリースは**上流の挙動を採用**します: 新しい書き込みは各プロバイダーの実際の `model_provider` id を保持し、カスタムルーティングキーは `custom` に統一されます。挙動変更の詳細はアップグレードノートを参照してください。

### モデル & 価格カタログのリフレッシュ

- デフォルト Claude Opus を **4.8** に引き上げ。
- ShengSuanYun のプレフィックス付きモデル ID を修正; GPT 5.5 を追加。
- OpenCode Go プリセットをリネームしてモデルサフィックスを削除。
- OMO 推奨モデルをリフレッシュし、「推奨を入力」フィードバックを改善。
- Rust の `database/schema.rs::seed_model_pricing` とフロントエンドの `src/config/*Presets` を一貫させ、旧価格のまま残る行を更新する冪等な価格修復パスを実行。

## 修正

### Codex: 非 ASCII モデル名でのセッション同期 panic

`normalize_codex_model` は以前、ISO 日付サフィックスを剥がすためにモデル名の末尾 11 バイトをスライスしていましたが、そのスライスが UTF-8 文字境界に落ちるかを確認していませんでした。非 ASCII モデル名（例: `【官】glm-5.1`）は panic を引き起こし、本フォークの 60 秒バックグラウンドセッション同期タイマーをダウンさせていました。現在このスライスは `is_char_boundary` とサフィックスの ASCII チェックで二重に保護されています。

### プロキシ: DeepSeek / Anthropic ツール思考履歴の正規化

プロキシが DeepSeek の Anthropic 互換ツール思考履歴を正規化するようになり、サーバーモードの Claude 互換 / DeepSeek ルーティングの正確性が向上します。

### Deeplink: Claude プロバイダーインポート時のカスタム env フィールド保持

deeplink 経由で Claude プロバイダーをインポートする際、インライン base64 config の完全な `env` ブロック（存在する場合）を起点とし、その上に標準の URL パラメータフィールドをマージするようになりました。これにより、ユーザーが渡したカスタム環境変数がインポート後も残ります。

### About: プレリリース対応のツールバージョン比較

ツールの「更新あり」検出が、文字列の `!==` ではなく軽量な semver 比較（`src/lib/version.ts`）を使うようになりました。公開されている `latest` より*先行する*ローカルインストールのプレリリース / next チャネル CLI バージョンが、恒久的な誤った「更新あり」表示を引き起こさなくなりました。

## ⚠️ アップグレードノート

### Codex `model_provider` アンカーを削除

以前のフォークビルドは、CC Switch のプロバイダー切り替えをまたいで Codex の resume 履歴がグループ化され続けるよう、Codex ライブ `config.toml` の `model_provider` を安定した内部 `ccswitch` バケットに書き換えていました。本リリースは上流と整合させるためそのアンカーを削除します: 新しい Codex ライブ書き込みは各プロバイダーの**実際の** `model_provider` id を使います。その結果、既存フォークユーザーの Codex resume 履歴バケットキーがアップグレード後に変わる可能性があります（デスクトップのみ、影響範囲は狭い）。上流の一回限りの Codex 履歴連続性マイグレーションは後続タスクへ**延期**されます; 連続性が重要な場合は、そのマイグレーションが出るまで該当の Codex セッションを保持してください。
