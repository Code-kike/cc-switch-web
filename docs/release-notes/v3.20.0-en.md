# CC Switch v3.20.0

> Synced product-upstream `farion1231/cc-switch` `v3.19.2..v3.20.0` into this Web-first fork via selective port. The standalone Web-server deployment model, dual-runtime parity, the no-auth posture, the disabled desktop updater, and the existing Web hardening are all preserved. This release also lands the three large new features of the cycle: the Pi native coding agent, Codex Alpha WebSearch, and managed OAuth account selection.

## Highlights

### New Features

- **Pi native coding agent** — Pi joins the fork as a first-class provider app: provider management, presets and model catalog, native `AGENTS.md` prompt files with a template library, session discovery and session-usage import, and a skills safety path that preserves uninstall state and validates path aliases. Nine new Web commands are registered and route-checked, so Pi works identically in the browser and on the desktop. Session-usage import ships a `v16 -> v17` schema migration that adds a semantic dedup ledger.
- **Codex Alpha WebSearch** — Codex's Alpha Search endpoint is served through the local proxy (four local aliases), and Claude-side hosted WebSearch is translated end to end: request translation, a streaming response bridge, non-streaming responses, usage accounting, and ~30 markdown citation primitives. URL derivation is fail-closed: an opaque full URL that does not literally end in `/responses` is rejected instead of guessed at. Five quadratic-cost caps bound citation dedup on untrusted text (worst observed case 6.7 s -> 116 us).
- **Managed OAuth account selection** — providers can bind to a specific managed OAuth account (Codex / Copilot / xAI) instead of "whatever is logged in". Only the account id is persisted; OAuth secrets are stripped on save, and an account that needs re-authentication is refused rather than stored. For managed Codex Official cards the selected account's bundle is written into the Codex live `auth.json` so its field shape matches a native browser login. Under local-routing takeover the fork opens **only** managed Official cards — unbound native-login Official cards stay refused at switch time, because this fork resolves the bound account server-side rather than forwarding the client's inbound `Authorization`.

## Fork-Specific Deviations

- The `zh-TW` locale and `README_DE` are not restored; upstream hunks touching them were dropped as no-ops.
- The `claudeDesktopProviderPresets` surface and the desktop-only sponsor banner tables in the READMEs remain excluded, so upstream's desktop-preset and README-partner hunks were dropped as no-ops.
- The Codex Chat routing stack (`streaming_codex_chat.rs` / `transform_codex_chat.rs` / `codex_chat_common.rs` / `transform_codex_anthropic.rs`) remains an intentional carry-forward deferral. Upstream commits touching only that stack were skipped as proven-inapplicable: `3f75bbdf` (StepFun effort), `46f19a15` (DeepSeek cache-hit tokens, transform layer), `d01eab97` (OpenCode Zen reasoning), `6a7da87c` (grokbuild input token details), and the transform/UI layer of `40cac1a6`. Restoring the stack requires porting the full ~5.7k+ LOC dependency base first.
- The `36ed280d` i18n labeler glob fix was skipped because the fork has no `.github/labeler.yml` (config) nor `workflows/labeler.yml` (workflow). Its intent — correctly recognizing `src/i18n/locales/**` as an i18n path — is equivalently covered by the inlined path filters in `c98cc3a9` (the `src/**` group).
- The `7e5007d5` / `619a592c` Claude Desktop form commits were skipped as proven-inapplicable (the fork has no `ClaudeDesktopProviderForm.tsx`). The `390102a2` OpenCode Go DeepSeek contextWindow commit was skipped (the fork has no "OpenCode Go" preset, and the fork's DeepSeek official preset already carries `contextWindow`).

## Notes on the Three New Features

Each shipped as its own planned, gated and archived subtask, with these fork-specific rulings:

- **Pi** (`84e75ad2` + `40d747c0`) — ported as a purely additive provider; non-Pi paths were not refactored.
- **Codex Alpha WebSearch** (`bdeaac75`) — one function from the deferred Codex Chat stack was needed and was ported as a **private** helper in its single consumer, with its necessity mutation-proven; the deferred stack itself remains absent.
- **Managed OAuth accounts** (`a2e22f33` + the managed-codex transactions of `0455a92c`) — upstream's `migrate_legacy_codex_official_managed_binding` startup migration is deliberately **not** ported: upstream deleted it before `v3.20.0`, and it would have moved the user's current provider off the fixed `codex-official` id. The takeover carve-out is narrower than upstream's (managed cards only, see above). The Official-takeover predicate in `providerCapabilities.ts` / `ProviderCard.tsx` / `useProviderActions.ts` therefore diverges from upstream on purpose.

The `zh-TW` locale and the Claude Desktop provider form remain out of scope in all three.
