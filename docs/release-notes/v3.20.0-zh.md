# CC Switch v3.20.0

> 本次将 product-upstream `farion1231/cc-switch` 的 `v3.19.2..v3.20.0` 通过选择性移植（selective port）同步到 Web-first fork。独立 Web 服务部署模型、双运行时 parity、无认证姿态、已禁用的桌面 updater 与既有 Web 安全加固全部保持不变。本版同时落地本轮三个全新大特性：Pi native coding agent、Codex Alpha WebSearch、managed OAuth 账号选择。

## 重点

### 全新特性

- **Pi native coding agent** —— Pi 作为一等供应商应用加入 fork：供应商管理、预设与模型目录、带模板库的原生 `AGENTS.md` prompt 文件、会话发现与会话用量导入，以及保留卸载状态、校验路径别名的 skills 安全路径。新增 9 个 Web 命令已注册并纳入路由校验，因此 Pi 在浏览器与桌面上行为一致。会话用量导入附带 `v16 -> v17` schema 迁移，新增语义去重账本。
- **Codex Alpha WebSearch** —— Codex 的 Alpha Search 端点经本地代理提供服务（四个本地别名）；Claude 侧 hosted WebSearch 完整转译：请求转译、流式响应桥、非流式响应、usage 计算，以及约 30 个 markdown 引用原语。URL 推导为 fail-closed：不以 `/responses` 字面结尾的不透明完整 URL 直接拒绝，而非猜测。五个二次开销上限约束不可信文本上的引用去重（最差实测 6.7 s -> 116 µs）。
- **managed OAuth 账号选择** —— 供应商可绑定到具体的托管 OAuth 账号（Codex / Copilot / xAI），而不再是「当前登录的那个」。只持久化账号 id；保存时剔除 OAuth secrets，需重新认证的账号**拒绝保存**而非存下。对托管 Codex Official 卡，所选账号的 bundle 会写入 Codex live `auth.json`，使其字段形状与原生浏览器登录一致。本地路由接管下 fork **仅**放开托管 Official 卡 —— 未绑定的原生登录 Official 卡仍在切换时被拒，因为本 fork 在服务端解析绑定账号，而不转发客户端的 inbound `Authorization`。

### 上游同步（批次 S1–S7）

- **S1 文档/预设/i18n**：在所有受支持应用中注册 PPIO、JieKou AI 与 XycAi 三个合作伙伴预设（含品牌图标，受支持的预设类型还附带端点回退）；RunAPI 预设迁移到 `runapi.host`（保留 `runapi.co` 作为回退端点）；移除主面板供应商卡片上遗留的合作伙伴 ⭐ 徽标（合作伙伴星标只在预设选择器中显示）；各语言加入 `xycai` 促销文案；版本号升到 3.20.0。
- **S2 安全/数据完整性**：env-check preflight 挂起修复；不再覆盖 Codex ChatGPT 登录（上述 managed OAuth 账号的前置）；Kimi thinking 注入停止；zhipu `CREDIT_LIMIT` 配额；routing 动画激活；sync/restore 一致性（事务化 restore，每表 prepare-once INSERT）；backup SQL 保真度（多行 `VALUES` 批处理，trigger/index 顺序）。fork 的 canonical-schema allow-list、backup/replace 锁边界、2s JS deadline、16 MiB heap / 256 KiB stack 上限与 SQLite authorizer 严格性全部保留。
- **S3 定价/usage**：DeepSeek V4 peak + Gemini 3.7 Flash 种子；DeepSeek catalog 镜像抽取；Grok 4.5 cached + Grok 4.6 + DeepSeek alias；多年趋势 tooltip；DeepSeek cache-hit tokens。FE-preset ↔ Rust-seed 一致性门禁通过（无 `cost=$0`）。
- **S4 codex/provider**：移除 Goal 模式 toggle；恢复 1M context toggle；IME-safe provider 字段（新建共享 `ImeSafeInput`，Hermes/OpenClaw/OpenCode 表单采用）；取消过期 device login；Grok Build Codex 复制；grokbuild 表单对齐；macOS IME 损坏修复。`0455a92c` 多 follow-login 与 `897ca892` OAuth usage 拆分（前端增量在此；Rust managed-codex 事务随上述 managed OAuth 账号一同落地）。`40cac1a6` 每模型 reasoning levels 拆分（catalog 数据层落地；转换/UI 层延期）。
- **S5 UI/refactor**：Hermes/OpenCode/OpenClaw 表单层级对齐；checkbox 样式统一（Radix → 原生 `<input>`，保留 `onCheckedChange`/`checked` 契约）；OpenClaw 模型编辑器；model-dropdown 整合；fuzzy model dropdown（新建 fork 从未承载的共享 `ModelDropdown.tsx`）；Claude 高级选项对齐；缩减编辑器空白；GrokBuild glass 容器；skills `check_updates` 现在把缺失 SSOT 目录报告为 update。

- **S7 CI**：当 PR 既不触及前端也不触及后端时跳过对应检查（适配到 fork 的 3-job `frontend`/`backend`/`web-server` 结构，新增 `changes` job 使用 `dorny/paths-filter`，SHA-pinned）。

## 三个新特性的补充说明

三者各自作为独立子任务完成规划、门禁与归档，fork 特有裁定如下：

- **Pi**（`84e75ad2` + `40d747c0`）—— 按纯新增 provider 移植，不重构非 Pi 路径。
- **Codex Alpha WebSearch**（`bdeaac75`）—— 延期 Codex Chat 栈中有一个函数确实必需，以**私有**函数形式落在其唯一消费者内，必需性经变异验证；延期栈本体仍缺席。
- **managed OAuth 账号**（`a2e22f33` + `0455a92c` 的 managed-codex 事务）—— 上游的 `migrate_legacy_codex_official_managed_binding` startup 迁移**有意不移植**：上游在 `v3.20.0` 前已删除它，且它会把用户当前供应商从固定 `codex-official` id 上搬走。接管 carve-out 比上游窄（仅托管卡，见上）。因此 `providerCapabilities.ts` / `ProviderCard.tsx` / `useProviderActions.ts` 中的 Official-takeover 谓词与上游有意分歧。

`zh-TW` 语言与 Claude Desktop 供应商表单在三者中同样不在范围内。
